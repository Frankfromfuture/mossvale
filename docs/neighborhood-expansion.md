# 小镇扩建与独立住宅

2026-10-13。本轮落地在本机 2D 共用世界，先验收 `?view=grid`。像素版读取同一布局和存档；两个独立 3D 工程未更新。

## 已实现

地图由 56×40 米扩大到 80×64 米，面积约为原来的 2.29 倍。原咖啡街、工坊、书屋和经营设施保留，新增东篱果园、西风草坪、溪畔苗圃、林间茶歇。果树、花草、水池、长椅和桌上的书沿用现有物件动作；公共地点加入居民日常选择。

榆树里、南风巷各有六户，共十二套 8×8 米住宅，覆盖村长与十一位常住居民。每户有独立地址、床、桌椅、灯、书或盆栽和门前花草。原 `home` 公共长椅仍保留，居民睡觉与在家休息改去本人住宅。离线村长也回自己的家。游客住酒店，已归档的叶小满不重新加入常住人口。

网格地图分为“公共去处”和“各家住址”，按页列出可点选的目的地；村民档案也显示住址并支持步行前往。对话和纸张 UI 沿用当前规范。住宅门保持开放，拜访邀请、访客权限与室内装修尚未实现；邻居的床和家具有服务端所有权限制，住宅不产生公共维护报酬。

酒店由 20×24 米收紧到 16×20 米，占地减少 33.3%。四个房间编号保留，两间基础房仍具备床、灯、桌椅，另两间继续等待布置。保留前台、共用卫浴和小型茶歇大厅。家具、订房和账本继续使用原有标识。

旧档第一次加载前保存 `.before-neighborhood-v1`。已有酒店家具按原房间迁移；承载物跟随桌面，放不下的家具保留在仓库。入住记录、预留资金、账本、物品状态、聊天与居民记忆不重置。迁移发生在离线结算之前，新地址上的活动路线重新计算。

物件编号扩展为允许两位数字，以容纳新增家具。网格物件按可见范围启用绘制，视野不变时复用结果；这项调整减少屏幕外绘制，不代表已完成手机真机性能验收。

## 下一步建议

1. **先做拜访与门牌互动。** 查看主人是否在家，敲门、约时间做客，离开后记下一条共同经历。这样住宅会参与人际关系，而不只是睡觉的坐标。
2. **再做家庭布置。** 给村长家单独的家具仓库和摆放规则，居民家随性格出现不同摆设。酒店家具与私人家具分开管理，避免共用仓库造成误操作。
3. **用公告板承接邻里委托。** 送书、送花、代购和维修可以复用现有物品与记忆系统。奖励来自明确的委托人账户，完成条件由服务器核验。
4. **给公共区安排真实活动。** 周末集市、草坪小演出或一起摘果子，优先让现有居民参与；天气和作息改变到场人数。

空间上优先改善入口与路线提示：酒店的前台、客房和卫浴可以加短门牌，住宅巷口标出街名。后续增加河道或山坡前，先观察新增街区的步行时长与相遇频率；若大家都耗在路上，再缩短连接道路或调整作息。

## 实现与验证

布局生成入口：`cocos-2d/scripts/expand-town.mjs`，在原地图基础上增量生成，可重复执行。若重新执行旧 `compose-town.mjs`，随后执行扩建脚本。

迁移入口：`server/neighborhood.mjs`。通行检查覆盖全部 26 个地点及十二户入口，夜间场景验证十二位常住角色各自回家。另使用包含 10,216 条事件的旧档副本，加入购置家具和桌面承载物，确认迁移保留资金、事件、记忆和父子关系，重复迁移不再修改存档。过程不调用模型，也不写入真实存档。证据位于 `cocos-2d/qa/neighborhood-evidence.json`。

正式 Cocos Web 构建完成一次。390×844 的后台 Chrome 验证了住址分页点击、回家寻路、村民住址资料和酒店四房状态；新增界面无运行错误。采样视野有 715 个可绘制物件节点，其中 71 个启用绘制。该数字只说明视野裁剪生效，不作为手机帧率结论。正式本机服务仍监听 127.0.0.1:4321，首次刷新旧会话时执行备份与迁移。
