# Jev：空闲选择与邻居反应

2026-10-13，已接入本机 2D。Jev 优先读取苔溪镇自己的加密服务配置；尚未单独配置时，才读取 Brizo 既有配置。新密钥保存在 macOS 的 `Application Support/Mossvale 2D Trial Service/model-guard.json`，使用 Electron safeStorage 加密，文件权限为 0600。密钥只在独立服务进程内解密使用；DeepSeek 继续读取 Brizo，Brizo 配置未改动。

## 当前分工

Jev 处理两类选择。居民完成工作、习惯或休息，有空决定下一件事时，服务器先筛出最多五个可到达的去处，再让 Jev 根据本人的性格、喜恶、近期经历和印象选一个。新的吃饭、睡眠、工作或邀请需要出现时，先完成这些安排。

居民做完一项休息或日常活动、附近恰好有空闲邻居时，双方分别判断：继续自己的事情、简短打招呼，或停下来聊聊。每次判断只带一个居民的内心资料，邻居只提供眼前身份、活动和本人对其已有的关系。涉及私事的记忆与印象不进入这类请求。

Jev 的结果通过服务器复核后，先执行点头、停留等反应。DeepSeek 先生成第一人的台词，通过检查并保存为实际发言后，再把这句原话交给第二人接话。第二人仍使用自己的人格、关系和过滤后的本人记忆；`heard` 只含发言事件编号、说话者名字和原话，不携带第一人的内心想法或记忆依据。原话属于转述，提及的行动不会因此变成事实。回复通过 `replyTo` 和事件依据关联上一句。DeepSeek 继续负责玩家对话和反思。

台词生成期间，已有任务照常推进；对方离开、开始新任务、玩家插话或交谈时间结束后，晚到的台词会丢弃。第一句失败或失效时结束本次台词生成，不再请求第二句；第二句失败时保留已经说出的第一句。一个居民选择独处，也不会凭空记录成双方已经聊天。2026-10-13 此次修改沿用原有 Jev 行动选择与私密资料过滤，最多仍为两次台词请求；顺序生成会增加第二句的等待时间。

本轮在独立内存小镇做了一次定向验收：正常接话使用两次真实 DeepSeek 请求，Jev 反应固定为聊天；另用本地受控响应检查礼貌婉拒和首句失败。确认请求顺序为第一句返回、记录保存、第二句请求，回复带有第一句原话与 `replyTo`；两人的人格保持独立，私密事件、派生印象、玩家聊天及说话者记忆依据没有跨人传递。记录见 `cocos-2d/qa/jev-sequential-reply.json`。本机 2D 服务已重启一次启用，服务端语法检查通过，无需 Cocos 重建。

实际首句仍出现了输入未记录的“上次说的那本书”，说明原有提示词并不能保证台词每个细节都忠于记录。本轮完成接话顺序和上下文隔离，未增加逐句事实核验。

## 执行与回退

2026-10-13 后续修订：用户撤回短句提速，优先保留对话的人情味与联想空间。现已恢复完整自主上下文、角色想法、原有 420 tokens 输出预算与 0.8 温度；不再要求通常 15–35 字。台词依旧遵循原有事实和私密信息规则，不把联想当作真实经历。

相遇台词改用 [DeepSeek 流式接口](https://api-docs.deepseek.com/api/create-chat-completion/)。只从 JSON 的首个 speech 字段提取文字，thought、行动字段和依据编号不进入气泡。未完成文字仅在服务内存和客户端展示，经独立轻量消息推送；不写存档、记忆或 heard。完整结果通过原有校验并记录后，第二人才收到原话。请求中断或场景失效会撤回草稿，第二句失败时仍保留第一句。

气泡按顺序播放，逐步出现并保留阅读时间；较长台词分段显示，回复不会立即挤掉上一句。播放时间按真实秒数计算。测试页也显示实时片段，下载记录包含首段文字耗时。这里的流式范围为 Jev 相遇台词，玩家聊天与反思保持原接口。

本机独立内存小镇完成正常聊天、礼貌结束及受控断流三个场景，共五次真实 DeepSeek 请求。首段可显示文字在 436–758 ms 到达，完整生成耗时 833–1147 ms；这些数值来自同次请求，不与上一轮网络条件不同的样本作速度排名。后台 Chrome 390×844 验证气泡在完整记录产生前开始显示，按顺序保留阅读时间，长句可显示后半段，断流草稿撤回；UTF-8 分片、转义字符、隐藏字段和结束标记也已定向检查。一次正式 Cocos 构建通过，没有加载或修改用户存档，不代表手机真机验收。结果在 `cocos-2d/qa/speech-stream-browser.json` 及同目录三个 `speech-stream-*.json` 场景记录中。下面的短句提速段落为已撤回的历史方案。

2026-10-13 台词提速：Jev 相遇后的 DeepSeek 请求改用台词专用格式，只生成短句和记忆依据。保留完整性格、价值与边界、喜恶、本人公开记忆、当前状态、关系和上一句原话，省去地点候选与日程规划，也不再额外生成内心想法。行动仍由已执行的 Jev 反应决定。第二句通过检查后立即接替第一人的气泡，每句保存一次；第一句仍先落入记录，再生成回复。玩家对话、反思和其他模型任务保持原流程。

同一台 Mac、同一 DeepSeek v4 flash 配置，用独立内存小镇对正常聊天和礼貌结束各测一组，修改前后各四次真实请求。平均输入从 2674 降至 1479 tokens，平均输出从 59.8 降至 29.8 tokens；单句平均耗时从 1.65 秒降至 1.41 秒，第二人的生成从 1.66–1.73 秒降至 1.14–1.40 秒。两句全部生成并发布分别从 3.67／2.95 秒降至 3.05／2.60 秒。这里固定 Jev 反应以比较台词链路，包含 DeepSeek 网络往返，不含画面绘制；小样本不代表长期保证。接话顺序、原话与 replyTo 关联通过检查；受控失败场景确认第二句失败时第一句仍保留，虚构的依据编号被过滤。未运行完整自动测试套件，也未改动用户存档。记录见 `cocos-2d/qa/speech-latency-before.json` 与 `speech-latency-after.json`。

- 仅在在线、短时间推进时产生新请求，离线补算沿用本地规则，不追补模型调用。
- 空闲选择每人至少间隔九十个游戏分钟；双方相遇反应至少间隔一百二十个游戏分钟。
- 每次请求最多等待三秒，最多三个并发；每镇每天最多三百六十次，全服务每天最多一千四百四十次，以 UTC 日期计数。该额度与 DeepSeek 分开。
- 连续三次请求失败或遇到限流后，暂停新请求一分钟。没有配置、超时、低把握或响应格式无效时，沿用人格规则。
- 初始采用 `confidence >= 0.55` 的接纳门槛；这是试玩参数，不代表人物选择正确率。模型选项、概率字段及取值范围均由服务器检查。

旧存档首次载入前保存 `.before-jev-v1`。反思、经历和人格文件保留。Jev 调用统计放在该小镇的 `jevUsage`，最近八十条决策记录放在 `jevLife.samples`，包含规则原选项、最终选项、耗时、回退原因和是否执行。界面沿用活动气泡和生活记录，不增加模型技术状态栏。

2026-10-13：生活记录增加选择、判断依据、Jev／规则接管和毫秒耗时；超时、额度或状态变化等接管原因单独列出。Jev 的依据是请求时的性格、身体状态、喜好与相关印象摘要，明确标注为输入摘要，并非模型返回的解释。耗时沿用真实请求计时，含接口往返，不含 DeepSeek 台词生成；查看记录不增加调用。正在执行的空闲选择立即可见，完成后随实际事件保存；相遇记录按查看的村民展示其本人判断。旧记录缺失信息如实标注，不反推历史原因或耗时。此项仅本机 2D。

## 更换密钥后的测试（2026-10-13）

新密钥最初沿用旧第三方网关，许知远和唐桃的两次请求均返回 HTTP 401。按 [TypeSafe 官方接口文档](https://docs.typesafe.ai/introduction/quickstart)将入口改为 `https://api.typesafe.ai/v1/systemone` 后，通过了认证。这两次失败单独保存在 `cocos-2d/qa/jev-key-endpoint-check.json`，不计入下面的正常接口测量。

在本机 Mac 创建独立的内存小镇，用正式服务的配置读取和行动执行代码测试许知远、唐桃。空闲选择和邻居相遇各做三轮，每轮两人，共 12 次 Jev 请求，另有 6 次 DeepSeek 台词请求。没有加载用户存档。

| 项目 | 请求数 | 请求耗时范围 | 中位数 | 执行结果 |
| --- | ---: | ---: | ---: | --- |
| Jev 空闲选择 | 6 | 322–612 ms | 340.5 ms | 3 次采纳，3 次低置信度后规则接管 |
| Jev 相遇反应 | 6 | 301–339 ms | 310 ms | 6 次采纳 |
| DeepSeek 台词 | 6 | 1087–1506 ms | 1337.5 ms | 6 次生成并记录 |

12 次 Jev 请求均正常返回，无超时、认证错误或无效响应。总中位数 326.5 ms，平均 369 ms。许知远三轮都选择去书屋阅读；唐桃三轮空闲选择的置信度低于既有 0.55 门槛，由规则安排去广场散步。相遇时双方都选择简短问候。

从触发测试到服务器实际应用空闲任务为 326–620 ms；相遇反应为 311–340 ms。双方台词从相遇触发算起，在 1456–1847 ms 后生成并记录。这里的时间包含接口往返，不含客户端轮询与画面显示；测试当时客户端约两秒同步一次，因此屏幕上的反应可能更晚。这次接口耗时比初次接入时短，但入口与密钥都换了，无法将差异单独归因于密钥，也不能据此推断所有村民的长期延迟。

原始逐次记录见 `cocos-2d/qa/jev-key-latency.json`，复测脚本为同目录 `jev-key-latency.mjs`。脚本仅通过 `MOSSVALE_ACCEPTANCE_ENTRY` 在独立进程中运行，不接触用户存档。正常配置优先级与脚本共用 `server/brizo-entry.mjs`；服务端配置变更后需重启一次，前端无需重建。

后续换密钥使用 `server/set-jev-key.mjs`，由无窗口 Electron 主进程从标准输入读取密钥，参数只允许非敏感的 `--endpoint=...`。`--endpoint-only --endpoint=...` 只更改入口并保留已有密文。脚本检查加密可用性及解密回读结果，日志只输出是否成功和接口地址。不要把密钥写入命令参数、仓库或客户端。

## 游戏画面的实时同步

本机 2D Web 使用 `/api/world-stream` 接收当前小镇的实时状态。居民选择落地后，沿用存档入口发布最新快照，不再等待下一次客户端轮询。相遇双方的台词也分别保存、推送，先生成的一句可以先到达客户端。推送不触发新的模型调用，原有服务器决策、模拟时间和寻路规则保留。

客户端仍每两秒发送玩家位置；实时连接正常时省去重复的全量查询，连接断开或十秒没有收到数据时恢复原轮询并尝试重连。切到后台、离开场景时关闭连接；回来时重新接收完整状态。Web 之外或不支持流式请求的环境继续轮询。

快照附带进程标识和递增序号，防止较早的查询、动作响应覆盖新决定。不同居民分别保留移动插值计时，别人的新决定或台词不会重置正在走路的人。服务器只保留慢连接尚未发送的最新快照，连接关闭时清理订阅。订阅沿用当前小镇的 Cookie／会话令牌与既有 Host、Origin 校验，不把会话令牌放进 URL。

2026-10-13 后台验收使用 Chrome、390×844 视口、4323 隔离服务与两份独立测试存档，实际调用 Jev 和 DeepSeek。4 次决定、2 句台词的快照均在发布后约 1 ms 被客户端应用，随后 25–42 ms 内观察到绘制帧更新。这是推送之后的同步时间，模型请求本身另需 311–754 ms，台词生成另需 1349–1982 ms；未作手机真机测试。

连接健康时没有 `/api/world` 轮询；人为中断推送后，原轮询接管并成功重连。较旧快照被拒绝，重复状态没有重置走路计时，人物节点实际发生移动，两份小镇的状态相互隔离。当前 2D 源码类型检查通过，完成一次正式 Cocos 构建；验收期间同一工作区的 UI 更新修复了构建包的脚本／引擎兼容问题，本轮保留其修改后完成上述验证。未运行全套游戏测试。证据见 `cocos-2d/qa/realtime-check.json`；本机 4321 已重启启用。

## 2026-10-13 实验阶段取消日额度

按用户要求，本机 2D 启动时默认启用 `MOSSVALE_UNLIMITED_AI=1`。DeepSeek 的每日总调用、自主调用和反思调用额度，以及 Jev 的每日调用额度均不再拦截请求，包含服务级总额度。统计字段继续累计。模型超时、最多同时三个请求、失败退避，以及居民原有生活和反思节奏保留。显式设置 `MOSSVALE_UNLIMITED_AI=0` 可恢复原额度。

本次以模拟接口验证超过旧额度后仍能调用并累计用量，关闭实验开关后额度仍可生效；验证没有调用真实模型。只修改服务端及本机 2D 启动配置，无需重建 Cocos 客户端。原先受额度限制的十分钟采样已停止并单独保留，启用后重新计时。
