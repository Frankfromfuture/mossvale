# 苔溪镇居民档案

更新：2026-10-13。每位居民有一份 `soul.md` 和一份 `memory.md`，共 12 组。

`soul.md` 写这个人通常怎样理解事情、在乎什么、遇到冲突会怎样反应。`memory.md` 写他经历过什么、听说过什么、目前怎样看待别人，以及还有哪些约定要兑现。接入后，两份文件共同参与下一次决策。

人格已在 Cocos 版本运行。服务器启动时读取十二份 `soul.md`，校验角色 ID 和性格数值；稳定性格用于对话，也影响日常选择。本机 2D 已进一步接入个人作息、习惯与有来源的可修订印象，详见[反思与习惯](../reflection-habits.md)。`memory.md` 仍是开局模板，运行经历和印象保存在各小镇自己的 JSON 存档里，原来的记忆和关系保留。完整长记忆格式与 Markdown 写回尚未接入。

## soul.md 的字段

每份文件有一个 YAML 数据块，版本为 `mossvale.soul.v1`。`resident_id` 沿用现有代码 ID，包括阿澈的 `a`。基础身份、背景、五维数值及说话风格继承原档案；细分特征、需求、矛盾和情境反应属于本轮编写的游戏设定。

数值范围为 0—100，表示相对倾向，50 是中间值。它们是调节游戏表现的参数，没有经过心理测量，也不表示某次行为必然发生。五维值与细分值独立保存，细分值不按平均数反推五维值。

| 字段 | 含义 |
| --- | --- |
| `extraversion` | 社交主动与社交精力 |
| `conscientiousness` | 做事有安排、履行责任的倾向 |
| `openness` | 对新想法、体验和创作的兴趣 |
| `agreeableness` | 合作、体谅和协调关系的倾向 |
| `emotional_sensitivity` | 对压力、拒绝和不确定情境的敏感程度，越高越敏感 |

旧 `traits` 数组在新格式中按以上顺序命名，避免把未注明含义的五个数字直接交给模型。

`facets` 把容易混在一起的特点拆开：

| 字段组 | 中文含义 |
| --- | --- |
| `assertiveness` / `warmth` / `social_energy` | 敢表达意见 / 待人亲近 / 社交精力 |
| `orderliness` / `reliability` / `deliberation` | 条理 / 可靠 / 决定前考虑的程度 |
| `curiosity` / `imagination` / `flexibility` | 好奇 / 想象 / 调整做法的意愿 |
| `empathy` / `accommodation` / `boundary_assertion` | 理解他人感受 / 迁就 / 表达并维护边界 |
| `stress_reactivity` / `rumination` / `recovery_speed` | 压力反应 / 反复想着一件事 / 情绪恢复速度 |

恢复速度越高表示恢复越快。边界清楚和体贴可以同时很高，内向和敢于表达也可以同时存在。`needs` 分别表示亲近、自主、安全、成就、新鲜感和安静的长期偏好；当天是否疲劳另取运行状态。

`values.priority` 中 1 为最高优先级。`inner_conflicts` 记录想要什么、担心什么、习惯怎样保护自己、在什么经历下愿意尝试改变。`emotional_triggers` 描述短期反应及缓和条件。`decision_patterns` 给出通常选择和例外条件；钱、工具、拍照等尚无对应玩法的情境，只用于人物设计与后续人格检查，不代表游戏已开放这些操作。

`goals.active_commitments_source` 用 `file` 和 `field` 指向同一居民记忆中的约定字段。

`speech.example_lines` 是语气示例。模型按当时的事实说话，示例台词不进入记忆库，也不证明台词里提到的事情发生过。

整份 `soul.md` 由作者维护版本。运行中的模型只提出行为和记忆解释，不修改身份、过去经历或基础性格。关系、认识和习惯可以随经历更新；更改稳定性格需要单独的人物版本修订，并说明变化依据。

## memory.md 的长记忆

版本为 `mossvale.memory.v1`。模板的 `town_id` 为 `null`、`revision` 为 0，动态记录留空。初始背景使用 `resident_id:seed:序号`；人物看法使用独立的 `belief` ID。`authored_seed` 表示编剧给定的虚构背景，不能伪装成运行中发生的 `e123` 事件。

| 区域 | 保存的内容 | 保留方式 |
| --- | --- | --- |
| `long_term.autobiographical_memory` | 人生经历、长期自我认识；运行后加入有来源的重要经历 | 保留原始来源，检索时选用相关部分 |
| `long_term.beliefs` | 对自己、别人或环境的暂定理解 | 保存支持证据、反对证据和修订版本 |
| `long_term.relationship_summaries` | 与某人的相处概况、熟悉度、信任等 | 由真实往来更新，每项结论可追溯 |
| `long_term.player_relationship` | 对本存档玩家的认识 | 新游戏从初值开始，旧游戏继承原状态 |
| `long_term.learned_preferences` | 相处后学到的偏好，如对方喜欢安静的见面方式 | 标明谁表达或怎样观察得知，允许改变 |
| `commitments` | 已接受但尚待履行的约定 | 在兑现、取消或违约前一直可触发 |
| `recent_episodes` | 最近的亲历和直接观察 | 保留原事件，重要部分整理进长记忆 |
| `reported_information` | 别人说过的话，包括传言和自我报告 | 保留说话者及传播路径，和事实分开 |
| `open_questions` | 仍未确定的事情 | 得到新信息后继续核对 |
| `daily_summaries` | 一天实际经历的摘要 | 附来源，避免把摘要再次算作新事件 |
| `revision_log` | 看法、偏好和摘要怎样变化 | 追加记录，保留旧版本 |

空字段代表尚无记录。`null` 表示未知或尚未初始化，不能当作数值 0。模板中的玩家信任 30 沿用当前新游戏默认值，其余关系维度是拟增字段，不自动从熟悉度推算。

`occurred_at` 和 `recorded_at` 采用服务端游戏总分钟数。发生时间不详时保留 `null`，用 `occurred_label` 记录“大学期间”等已有描述。真实世界的保存时间另存 ISO 时间戳。代码不得把模板制作日期当成故事发生日期。

### 运行记录的格式

下面是字段示意，空值不是发生过的经历。每位居民文件中的空数组在服务器确认事件后再填充。

```yaml
# recent_episodes 中的一条确认经历
id: null                       # 由服务器生成，在该小镇内唯一
kind: fact
content: null                  # 只描述已确认的行动与结果
source_event_ids: []            # 必须存在于当前小镇事件库
occurred_at: null
recorded_at: null
participants: []
known_by: []
perception: null                # direct_participation 或 direct_observation
importance: null               # 整数 1—10
privacy: private
status: active
```

```yaml
# reported_information 中的一条听说的信息
id: null
kind: reported
content: null
source_event_ids: []
speaker_id: null
known_by: []
transmission_path: []           # 按实际交流事件记录说话者、接收者、事件 ID、时间
confidence: null               # 0—1；相信程度不改变其 reported 类型
occurred_at: null
recorded_at: null
privacy: private
```

```yaml
# commitments 中的一项约定
id: null
status: proposed               # proposed / accepted / fulfilled / cancelled / missed
subject: null
participants: []
known_by: []
place_id: null
due_at: null
accepted_event_ids: []
resolution_event_ids: []
```

只有双方明确接受才成为可执行的约定。截止时间到了也先核查到场、提前取消或其他实际事件，再决定是否标记失约。

### 保留与修正

普通闲聊可以按天整理，原始记录转入事件归档。原有信息不会因超过上下文长度被覆盖；模型每次只取需要的片段。高重要度经历、关系转折和未结约定进入长期索引，已经归档的事件仍能按 ID 查回。

看法和事实分别更新。例如，已经确认“对方没来赴约”就保留这条事实；后来对方说自己生病，先增加一条带来源的转述，再降低“他故意忽视我”这个判断的确定程度。取得进一步证据后继续修订。旧看法标记 `superseded`，新看法带 `supersedes`、支持证据、反对证据和更新时间。

相似记录合并时保留全部来源 ID。模型引用自己的旧台词、当天摘要或同一条转述，不增加独立证据数量。尚有冲突的信息进入 `open_questions`，等下一次可知事件补充。人物风格影响注意和解释，不改变事件是否发生。

“长期保留”只描述游戏中的遗忘和归档策略。玩家删除存档时，对应原事件、摘要、检索索引和记忆文件一起删除。

## 读写与隔离

拟接入目录分为设计模板和运行存档：

```text
docs/residents/<resident_id>/soul.md         作者维护的稳定人格
docs/residents/<resident_id>/memory.md       作者维护的开局模板
<save_root>/<town_id>/residents/<id>/memory.md   拟新增的每存档私有记忆
```

当前游戏没有创建最后一行目录。接入时由服务器把模板初始化为独立实例；两名玩家即使都认识林夏，经历也分别保存在自己的小镇里。版本升级不得用开局模板覆盖已发生的故事。

读取先检查 `town_id` 和 `known_by`，再检索相关性。其他居民的私有背景和秘密不会因为在同一数据库中就进入本人的提示词。转述必须有实际传递事件，每一跳只传播说话者获准分享的范围；每次只给模型当前角色有资格知道的内容。

写入由服务器负责。模型返回记忆或印象候选，服务器核对事件 ID、所有者、参与和感知资格、当前版本，再保存。以 `(town_id, resident_id, source_event_id, record_kind)` 去重；使用版本检查及原子替换，避免两次回应覆盖同一份记忆。事实由已执行的游戏行为产生，对话只能证明谁说过什么。

已有 `.data` / `.data-cocos` JSON 迁移时先做备份，保留事件编号、时间、信任、原始聊天和现有承诺；旧的 `reported` 继续保持转述类型。种子背景按稳定 ID 去重。来源缺失的旧印象保留并标记待核对，不升级为确认事实。先将一份存档迁移并核对，再接入新的写回流程。

## 每次思考读取什么

固定读取人格摘要、当前目标和边界，按当前情境选取相关触发条件与行为倾向；临时情绪、位置和资源从世界状态获取。

记忆先取即将到期的承诺、相关人的相处摘要、与当前事件相近的重要经历，再补近期交流。建议先保留现有的最多 7 条检索记忆和最近 6 条聊天消息，以实际延迟与行为表现调整预算。长期存储量与单轮输入量分开，不把整个人生档案逐轮重复发送。

检索候选可沿用相关性、重要度、近期程度，再加当前目标匹配；长期关键经历即使很旧，也不应仅因时间衰减就永久取不到。向量检索属于待实现功能，当前原型仍按文字重合度检索。

完整过程：

```text
本人可知的事件 → 服务器记录 → 整理事实、转述和看法
            → 私有长记忆检索 + soul 摘要 + 当前处境
            → 模型提出反应 → 规则检查并执行 → 下一条实际经历
```

性格影响愿意做什么，资源和规则决定能做什么，经历影响愿意怎样对待某个人。信任变化后续应结合事件影响、是否重复、人物看重的事与补救行动计算；`帮忙固定 +7` 仍是当前代码行为，本轮文档没有替换它。

## 接入后的验收场景

同一问题允许出现不同的自然回答，不检查是否复述示例台词。

1. 邀请参加大聚会：林夏看店务安排，许知远询问人数和离场方式，陈默看手头工作。许知远答应安静的小聚也符合人设。
2. 帮忙、失约、解释、再次兑现：分别保存四类经历；能够讲清自己为什么改变对玩家的看法，重启后仍能检索到依据。
3. 只告诉一位居民秘密：其他居民在实际获知前保持不知情；转述之后能指出传播来源。
4. 道歉或送礼：回应可以缓和，重要失约的记录仍保留；相同举动对不同人物的影响应有区别。
5. 连续七个游戏日：允许学会表达边界、改善相处方式，同时保留可辨认的性格；换存档后不会带入另一个玩家的故事。

这些仍是长期验收目标。本轮已检查人格加载、不同活动选择、登录刷新去重、存档保留和记忆边界；连续七天的人格稳定性尚未验收。

## 运行中的人格与登录更新

`soul.md` 的 `daily_life` 保存个人偏好的地点、早午晚节奏、与目标有关的地点、活动时长、活动台词和回应方式。程序结合安静需求、社交精力、好奇心、到访间隔、路程、体力和饥饿选择下一件事。私人经历里有明确地点的相处记录可以影响重访意愿，失约记录也会起作用；选择的依据附在计划上，计划本身不算完成事件。

每次进入调用 `/api/arrive`，更新十二人的下一步打算和当前活动台词。进行中的行走、活动、交谈和赴约继续执行，结束后再采用仍然有效的计划。雨天、营业时间和身体状态变化时重新判断。重复提交同一次进入标识不重复刷新，也不增加关系或物品；不同的进入请求不会凭空推进游戏时间。

离线时间仍按原服务逻辑补算，上限为 1440 个游戏分钟。手记的“你离开时”只摘录上次玩家位置同步之后实际产生的活动与相遇，最多三条，每条都保留事件编号。登录刷新现已为十二人异步调用模型，邻居间的开口与回应分别调用，各自只使用本人上下文。规则负责执行、离线补算和失败时继续生活。详见[自主生活实现](../autonomous-life.md)。

旧存档升级前保存 `.before-personality-v2` 备份，只补入人格版本和摘要，不重置信任、口袋、约定和动态记忆。个性化的“一起做”关系增量按亲近需求及是否重视这类劳动计算，范围为 2—6；原有“帮忙”与“赠礼”仍沿用既有规则。
