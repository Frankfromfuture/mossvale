当前有 23 种部件定义、605 个场景实例，其中 384 个是独立地块，其余是墙、门、桌椅、书架、植物、器具和小物品。每个实例拥有唯一 ID、独立 Cocos 节点和可查询的完整属性。材质里的木纹、草纹属于贴图细节，不另做游戏物件。

## 数据与画面的对应

`cocos-2d/scripts/compose-town.mjs` 负责定义部件种类和拼装街区，输出 `object-catalog.json` 与 `town-layout.json`。绘制和服务端读取相同的数据。修改拼装脚本后执行 `node cocos-2d/scripts/compose-town.mjs`，再统一构建。

类型定义保存材质、重量、尺寸、最大耐久、碰撞、可搬动性、默认动作及类型专有属性；场景实例保存位置、朝向、归属、所属场所和承载关系。同类物品共用类型规则，各自的状态独立。数值为当前试玩使用的游戏参数。

存档只保存发生过变化的实例字段；查询时将类型、初始实例与存档变化合并。地块也有自己的 ID、材质、状态和互动，未将整片地面作为一张背景。

| 部件 | 独立状态与动作 |
| --- | --- |
| 地面、墙 | 清洁、耐久；整理或维修 |
| 门 | 开关；关闭后进入碰撞与寻路计算 |
| 桌子、柜台、书架 | 清洁、耐久、承载物品；搬动、旋转或翻书 |
| 椅子、长椅 | 占用者、占用时间；坐下、休息、搬动 |
| 杯子、书 | 杯中余量、阅读时间、使用次数；饮用、阅读、单独摆放 |
| 咖啡机 | 豆子存量、容量、使用次数；制作咖啡 |
| 植物 | 湿度、生长、果实或修剪时间；浇水、采摘、修剪 |
| 木箱 | 木料存量、容量；取出、存入、搬动 |
| 木工台 | 耐久、使用次数；消耗木料制作木板 |
| 喷泉、提灯 | 水流、灯光；开关、装水 |
| 石块 | 位置、材质、重量；拾取后从场景移除并进入口袋 |

桌上的杯子和书分别存在，记录自己放在哪张桌子上。搬动或旋转桌子时，服务器一起更新承载物的位置；单独搬开杯子时解除原承载关系，放到合适桌面上则建立新关系。

## 操作

轻点物件会先走近，再执行它的常用动作。长按约 550ms 打开目标菜单，“看看”可翻阅属性手记。轻点地面继续寻路，长按地面可检查那一块地。

选择“搬动”后，角色先走近物品，再出现摆放预览。轻点附近位置提交；长按、点取消或按 Escape 退出。家具会检查尺寸和已有物品，也会检查人物与通路。开关门或挪动家具后，玩家和居民使用更新后的碰撞；被关门挡住的居民会等待通路恢复。

## 保留的接口与新增接口

原有 `/api/world`、`/api/presence`、`/api/interact`、`/api/activity`、`/api/arrive` 等继续使用。模型配置读取、人格、交谈和记忆服务保持原接口。

新增接口只在 `cafe-2d` 服务启用：

| 请求 | 用途 |
| --- | --- |
| `GET /api/objects` | 查询全部实例合并后的属性 |
| `GET /api/objects/:id` | 查询单个实例及承载物品 ID |
| `POST /api/object-action` | 提交部件动作 |

动作请求包含 `object`、`action`、该物件的 `revision` 和本次操作的 `requestId`。搬动时另带目标 `x`、`z`。客户端只提交意图；库存、耐久、坐标、关系和事件由服务器计算。

服务器检查会话、动作白名单、版本、距离、遮挡、库存、容量和摆放位置。同一操作标识重试只返回原结果。物件互动记录实际事件，附近能接触该物件的居民才获得相应经历。

## 存档与范围

仍使用 `.data-cocos-2d/` 和独立 `mossvale2d` 会话。旧 2D 存档首次载入前保存 `.before-objects-v1` 备份；人格、聊天、记忆和已有物品继续保留。原 3D 的 `.data-cocos/` 不参与迁移。

当前完成的是部件实例、属性、承载、互动、摆放、碰撞和持久化。居民日常活动仍以地点为单位调度；尚未实现 RimWorld 的建造施工队列、完整生产链、电网、温度传播和居民工作优先级。这些可继续接在现有部件结构上。

本版保持本机 Web 试玩。原远程 3D 仍需要 Mac 开机联网，2D 未新增远程入口。
