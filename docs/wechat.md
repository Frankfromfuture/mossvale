# 微信版本接入说明

## 本轮交付

`wechat/` 是原生微信小程序开发客户端，有地图、12 位居民、档案、记忆、聊天、邀请、赴约、天气及时间控制。它直接调用同一后端，不用 web-view 包装网页。

当前 `appid` 为开发占位 `touristappid`，`app.js` 的地址是本机 `http://127.0.0.1:4317`。本轮未打开微信开发者工具、未登录微信开发账号、未执行真机或上传审核。此目录是后续接入用的源码，不是已上线的小程序。

本机开发者工具与真实手机的网络环境不同：手机上的 127.0.0.1 指向手机自身。正式接入前提供 HTTPS 服务域名，在微信后台配置合法域名并填入自己的 AppID。保持域名和证书校验。后端当前只接受本机 Host，部署时应有明确的允许域名配置和反向代理，不要直接向公网暴露本机开发服务。

## 小程序还是小游戏

第一轮偏观察和交谈，原生小程序足够验证。随着地图、角色动画、场景切换和碰撞变复杂，建议迁往 Cocos Creator 2D 的微信小游戏输出。Cocos 的发布文档介绍了开发者工具和构建配置，资源管理可按场景进一步拆包。[官方流程](https://docs.cocos.com/creator/3.8/manual/en/editor/publish/publish-wechatgame.html)

目前地图是单张背景，居民是独立图集角色，走路以位置插值呈现。正式美术需要可拼接瓦片、入口、碰撞层、角色四方向动作和动画图集。公开素材可先验证，替换美术时保持逻辑坐标独立。

## 协议

| 请求 | 用途 |
| --- | --- |
| GET `/api/session` | 本地开发会话，返回随机存档令牌 |
| GET `/api/world` | 读取世界、居民、事件和调用状态 |
| POST `/api/interact` | `{resident, kind, message}`，交流或邀请 |
| POST `/api/control` | `{action, minutes?}`，天气、时间与赴约 |
| POST `/api/think` | 为指定居民生成有记忆依据的反思 |
| GET `/api/export` | 导出当前小镇存档 |
| POST `/api/reset` | 明确确认后重新开始 |

原生开发客户端用 `X-Town-Token` 保存本地会话，POST 请求带 `X-Mossvale: 1`。这属于本地原型身份标识，不是微信登录授权。网页端令牌放在 HttpOnly、SameSite Cookie 内。

上线时用微信登录兑换自己的短期服务令牌，由后端核对用户与小镇所属关系。API Key 保存在服务器的密钥管理服务，小程序只持有受限用户令牌。Brizo 本机凭据读取入口不随小程序分发。

## 云端需要补齐的部分

- PostgreSQL 世界与事件存储、事务、迁移、备份、删除恢复；角色检索强制 owner/town/resident 过滤。
- 任务队列保存 operationId、residentId、worldVersion、状态和超时；幂等结算，重启后恢复未完成请求。
- HTTPS/WSS 同步、网络重连、状态版本核对、低电量及切后台策略。
- 登录、集中预算、调用速率与全局开支保护；内容审核、举报、隐私说明和存档删除。
- 确认产品实际类目及当前平台要求，按目标产品办理所需材料。这里不预判审核结论或游戏资质。

先以一个小镇完成微信真机闭环，再扩到约 20 位内测玩家。网页上“能聊、会记得”通过后，微信侧主要验证通信恢复、设备性能和平台流程。
