# 玩家与村民的流式聊天

2026-10-13，已接入本机 2D Web。普通聊天及私下说话沿用原有 `context()`：人格、目标、状态、本人记忆与印象、约定、附近居民和最近对话均照常传入。没有新增摘要或缩短台词要求；保留原模型、0.8 温度、420 tokens 输出预算和原有输出校验。唯一新增的格式要求是把 speech 放在 JSON 的第一个字段，以便提前展示。

客户端在原 `/api/interact` 请求中接收逐段台词。草稿只通过当前请求返回，不进入邻居的气泡流；想法、行动和依据编号不显示在对话文字中。完整结果通过原有检查后才执行互动、保存两条对话记录并返回最终状态。玩家台词沿用原来的 800 字符校验上限，没有套用邻居闲谈的 90 字符限制。旧客户端及不支持流式读取的环境继续使用原 JSON 接口。

长回复仍可分页。文字生成时就可以翻到已有的下一页，完成后保留当前页。断流会撤下未完成文字，恢复之前的完整回复和发送内容；关闭交谈或进入后台会取消进行中的请求。每次发送带有独立标识，小镇保留最近二十次已完成请求的回执：最后一包丢失后重新发送同一次请求，可以取回已保存回复，不再调用模型或重复写入经历。失败重试保留这个标识，修改消息则开始一次新请求。

本轮在独立测试存档、后台 Chrome 390×844 中验证了以下场景，没有加载用户存档：

- 两次真实 DeepSeek 聊天，首次显示文字分别为 749、800 ms，完整响应为 1313、1262 ms；画面在完整记录产生前显示文字。第二次请求保留了第一轮的用户消息与回复。
- 受控断流发生在已有可见文字之后，未产生半句记录，输入和之前的完整回复均恢复。
- 重试返回 134 字完整台词，生成过程中可翻页，结束后仍停在当前页；再次提交同一请求没有新增调用或对话记录。

服务端语法、TypeScript 检查和一次正式 Cocos Web 构建通过。记录见 `cocos-2d/qa/player-stream-browser.json`，请求范围核验见 `player-stream-requests.json`。延迟是本机小样本，后台浏览器验收不代表手机真机表现。游客规则交谈、3D、远程与微信版本未接入本轮改动。
