轻点地点文字，玩家先沿路走近，再执行默认动作。长按地点可查看动作和价格；长按空地可打开手记、打开纸地图、休息一小时或切换雨天。每个地点活动完成后，间隔一个游戏小时再做，避免连点反复扣费或刷物品。口袋物品当前用于收集展示，食用和物品赠送另做；原有“送点心”仍按 10 币赠礼规则执行。

长按居民选择“一起做”，会先走近，再加入对方正在进行的活动。对方正在赶路、与别人交谈或回应玩家时，需要等一等；成功后保留共同经历，并按人物对相处和劳动的重视程度增加 2—6 点信任，同一居民一个游戏小时内只结算一次。

## 居民怎样生活

服务器按游戏分钟处理体力、饥饿、路径、活动和相遇。外向程度影响目的地偏好与社交间隔，责任心影响停留时间；每个人还有不同的日常去处。许知远偏向书屋与观景地，林夏会去咖啡馆、集市、北草坪和住宅区，陈默会去工坊、营地和苗圃。疲劳时歇脚，饥饿时去咖啡馆，夜晚回家；雨天转往屋檐下。已接受的下午茶安排优先保留。

同地点、距离足够近且有空的两位居民才会交谈或合作。在线交谈由双方分别回应，愿意继续聊时各增加 2 点关系；婉拒不扣关系。离线仍沿用规则相遇。事实记录说明谁在哪里做了什么，双方说过的话作为转述保存；第三位居民不会自动获得这段记忆。玩家加入活动时，只有在场并足够近的居民能记住。

登录意向和在线邻里交谈由模型生成，移动与活动结算由程序执行。玩家交谈继续调用原有模型，检索本人实际经历。`soul.md` 已接入对话和日常选择，`memory.md` 仍为模板。长期自主反思和复杂经济尚未实现。

## 存档与实现

`cocos/assets/resources/town-layout.json` 同时提供地点与碰撞范围，服务端和 Cocos 共用。居民路径保存在小镇 JSON 中，客户端插值已经批准的路径。`server/life.mjs` 负责生活调度、相遇、在场验证、活动结算与场景升级。

旧三人存档首次载入前备份为 `.json.before-life-v1`，再补入其余居民并初始化场景坐标。原有经历、聊天、信任和约定保留；升级标记防止重复添加。新经历、口袋和活动冷却随原存档保存。早期 2D 存档保持原逻辑。

远程试玩沿用原阿里云入口。网页与素材在云端，后端与存档仍在 Mac，Mac 需要开机联网。此次交付 Web Mobile 构建，微信正式上传和安卓真机帧率尚未验收。

地图第 2 版迁移前另存 `.json.before-layout-v2`。保留原有记忆、关系、活动冷却与口袋，只校正失效坐标、重算进行中的路径，并补入贝壳计数。原来的九个地点坐标保持。

操作增加拖住行走、松手停止。角落纸地图可点选八个片区的活动目的地，沿小路步行抵达；街区内的细分地点继续通过附近标签选择。
