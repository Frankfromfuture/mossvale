# 2D 部件验证记录

日期：2026-10-12。本轮使用隔离的试玩会话与后台 Chrome；没有操作用户窗口，没有运行自动测试套件。

## 构建与运行

- TypeScript 静态检查通过。
- 首次正式构建完成，但后台预览发现 Cocos 的集合展开编译结果有误，导致场景初始化中断。源代码改为 `Array.from`，并给更新循环补上初始化检查后，进行了第二次必要构建；Cocos 返回成功码 36，确认包含 CafeStreet 场景。
- 本轮 4321 后端只重启一次。补充构建后沿用该服务，后台页面加载正常，无 JavaScript 运行错误。
- 运行场景包含 605 个独立实体、605 个对应节点和 3 位居民。`GET /api/objects` 返回 605 项完整属性。

## 验证结果

1. 长按露台圆桌，菜单和属性手记正常显示；材质、重量、尺寸、位置、耐久、清洁、碰撞、归属及桌面物品均来自该实例。
2. 通过触控菜单搬动 `terrace-table-2`，从 (-4.8, -2.5) 移至 (-2.5, 0)。杯子与盆栽保留各自 ID，并随桌子移动；导航版本随之更新。
3. 轻点咖啡馆门，关门后该位置不再可通行；重新打开后恢复通行。
4. 使用同一个操作标识重放关门请求，返回原事件，没有再次切换门或增加导航版本。远处取木料请求返回 400，箱内库存未改变。
5. 刷新页面后，桌子、杯子、盆栽的新位置和门的状态保持。旧存档的 `.before-objects-v1` 备份与迁移前 SHA-256 相同，原有两条林夏聊天消息保留。
6. 单独轻点搬动后桌上的杯子，角色走近饮用。杯中余量变为 0，玩家精力由 80 增至 88；桌子自身版本保持不变。

这些检查覆盖本轮部件交互、最接近的小物件场景，以及服务端新增校验。未逐一执行全部类型动作，也未进行完整经营或十二居民回归。

## 性能采样

环境：本机 macOS 的后台 Chrome，390×844 CSS 像素、设备像素比 2、移动触控模拟。静止场景采样 120 个动画帧，间隔中位数 16.7ms，95 分位 16.8ms，无超过 50ms 的帧。这是桌面浏览器采样，不是安卓手机或微信实测。
