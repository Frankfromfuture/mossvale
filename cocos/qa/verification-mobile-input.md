# 手机输入与气泡修复验证

2026-10-11，远程测试页已更新，沿用原邀请链接。

根因：原布局在输入框聚焦时跳过重排，画布高度变化后原生 UI 相机仍按旧高度渲染，导致纵向压扁和 DOM 输入框错位；Cocos 的回车处理未区分中文组词。原气泡尾角用固定控制点单独绘制，形成圆舌形状和接缝。

修改范围：Mossvale.ts 同步 VisualViewport 与引擎尺寸，TownHud.ts 原地重排、保留输入节点、拦截组词回车、连续绘制短尾角；网页模板设置可见区域适配。设计要求已写入 design.md 和项目说明。

一次 TypeScript 检查通过，一次 Cocos Web 正式构建通过。构建后通过已有 SSH 连接更新阿里云静态资源，先上传新资源、最后替换入口；保留旧资源及入口备份，服务与存档未重启。

后台 Chromium 按安卓微信 UA 和 390×844 手机尺寸验证：
- 原问题复现：缩至 390×400 后气泡纵向压扁，文字浮在输入底板外。
- 修复后：相同缩屏中 HUD 高度为 400、UI 相机半高为 200；输入框范围 y=316…364，完全位于可见区域；输入节点和焦点保持不变。
- 通过 compositionstart、中文候选内容、isComposing 回车事件验证：仍在组词，未进入发送状态。
- compositionend 后恢复 390×844：保留“今天想喝一杯茶”，输入框范围 y=760…808，节点未重建。
- 正常回车发送后收到居民回复，同内容用户消息仅 1 条；没有运行时错误或警告。
