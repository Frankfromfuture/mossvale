# 流畅度修复验证

2026-10-11，已发布至原阿里云测试入口。

原因：游戏固定在 30 帧；静止气泡每帧清空并重建路径，每帧还分配临时向量与数组，重复更新停稳的镜头和界面节点。场景原有 GPU Instancing 已启用，本轮保持美术和材质不变。

修改限于 Mossvale.ts、TownHud.ts：目标帧率提高到 60；气泡轮廓变化时才重绘；复用帧循环向量和居民列表；镜头收敛后不重复更新，使用与帧率无关的阻尼；位置未变化的姓名标签不重复赋值。

## 同场景采样

独立后台 Chromium，桌面硬件，手机尺寸 390×844、实际画布 780×1688。固定玩家、居民及镜头位置，先预热 1 秒，再统计约 5 秒；气泡重建次数包含预热。结果不是安卓真机帧率。

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 实测帧率 | 30.0 fps | 60.0 fps |
| 平均帧间隔 | 33.33 ms | 16.67 ms |
| 帧间隔 P95 | 35.20 ms | 19.00 ms |
| 主线程更新至绘制提交平均耗时 | 3.63 ms | 2.64 ms |
| 主线程耗时 P95 | 4.50 ms | 3.60 ms |
| 绘制调用 | 87 | 87 |
| 气泡重建次数 | 183 | 2 |

主线程指标不含 GPU 完成时间。原始统计见 performance-fluid-motion.json。

## 本轮验证

TypeScript 检查通过；一次 Cocos Web 正式构建通过。对话气泡显示正常，390×400 输入缩屏后草稿、尾角和输入位置正确，恢复全屏正常。轻点街道后完成 17 个路径点，人物从约 (-2.76,1.97) 移至 (-0.55,9.04)，镜头随行，路径最终清空。

首次调试用全局 cc.MeshRenderer 探测组件时产生一次 3804（缺少类型）日志；该导出不在全局 cc 上，错误来自本次调试命令。后续游戏操作未出现新的应用错误。调试姿态与尺寸覆盖在结束时通过重新载入清除。

新静态资源先上传，入口最后替换；旧资源和入口备份保留。没有重启服务、改动存档或迁移模型凭据。远程交谈与存档仍依赖 Mac 开机联网。
