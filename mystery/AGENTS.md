# Mossvale 版本号与 GitHub 更新规则

- 每个用户请求算一次版本迭代；实现、微调和修复合并完成后递增一次版本号。
- 主要功能、核心玩法或大规模体验升级递增次版本，例如 `0.8.1 → 0.9.0`；小修复、界面微调、素材和文档更新递增补丁版本，例如 `0.8.1 → 0.8.2`。
- 同步更新根目录与 `mystery/` 的 `package.json`、`package-lock.json`，以及两处 README 的当前版本；包版本使用三段式，README 显示完整版本号。
- 在根目录 `CHANGELOG.md` 末尾按时间顺序追加本轮版本、北京时间日期和一句话改动说明，已有历史条目继续保留；同一请求中的多项修改合写一句，标明本地完成或实际上线的范围。
- 按修改范围完成必要验证后，将本次所属文件提交并推送到既有 GitHub 仓库，创建对应的 `v<版本号>` 标签和 Release；Release 概述本轮改动并链接完整更新记录，已发布标签保持原指向。
- 用户已授权今后的修改按上述流程同步 GitHub，执行时直接完成；其他请求的未提交改动留给对应迭代处理。
- 版本与 GitHub 同步沿用项目既有的存档、配置和发布边界；云端部署、真实模型与语音调用仍按各自授权范围执行。

## 纸页窗口内框规则

- 所有纸页弹窗共用 `src/paper-frame.mjs` 和 `.paper-window-frame`；装饰层放在滚动窗口外，边距、颜色和角花沿用共用样式，首页保持无框。
- 内框按当前可见窗口的实际尺寸定位；滚动正文、切换标签或故事页、内容展开、返回上一页和视口变化都要同步。不要在滚动容器中另加内框伪元素，也不要缓存上一次窗口的宽高。
- 新增或修改纸页窗口时，验证长内容滚动到底部及一次长短页切换，确认内框四边贴合窗口、不横穿正文、不影响点击；涉及手机适配时同时检查竖屏和尺寸变化。复用共用实现，不逐个窗口打补丁。

## 中英文介绍同步

- 根目录 README 的中英文区块是“关于 Mossvale”浮窗正文的共同来源，构建时随网页打包；介绍与图片使用本地资源，打开浮窗不依赖 GitHub 网络。
- 更新项目介绍时同时维护两种语言，不维护另一个浮窗文案副本；介绍区保持普通文档链接，不自动插入游戏人物或线索入口。

## 幕间与剧透边界

- 幕间正文由服务端按实际发现解锁；角色私有记忆不替代公开揭晓，未到达的幕间不进入页面数据或预加载图片。
- 自动幕间等待线索页、对话、朗读、输入和行走结束；阅读与跳过不改调查分数、证据、人物选择或结案结果。操作入口只引到对应页面，关键行动仍由玩家确认。
- 旧存档已完成的幕间直接收入「故事」，避免连续补播；阅读状态按角色槽位区分。新增场景复用故事册与共用纸页内框，检查跳过、重看及手机长短页切换。

## NPC 记忆边界

- 人物请求不传旧话索引，事实引用只接受当前facts编号；判定员保留原话编号供矛盾与重复问题核对，不放宽既有引用校验。
- 旧原话按说话人和实际听众检索，私谈问题不跟随同文公开回答传播；记忆只提供历史依据，不新增剧本事实或自动履行承诺。
- 案件与闲谈分配独立上下文空间，检索旧回答同时保留当前事实的优先级。旧档只从现有记录补回有依据的记忆，失败和同请求重试不重复写入。

## 物件图标范围

- 手绘物件图标只用于线索详情、物件介绍与菜单等界面；三维场景保留实体模型和搜证点击区，不叠加图标。

## 多剧本边界

- 第二部由 `server/scripts.mjs` 注册，业务与来源事实留在 `server/suspect7/`，前端只接收当前可见内容。第一部保持原规则。
- `scripts-v2` 兼容旧档只读映射；首次写入旧档前保留 `.before-scripts-v2`。剧本、路线和供述／调查视角切换都更新令牌，同名李察也更新。
- 第二部的阶段推论与正式核实结果分开保存；已删除资料保留缺口，结案不考精确定时拨号分钟。角色开放只要求首次结案。
- 资料与验证入口见 `docs/suspect7/README.md`，正式存档继续禁止用于测试。
