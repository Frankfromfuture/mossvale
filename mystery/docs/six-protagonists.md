# 六个主角视角（本地）

同一个案件可以从六个人的立场开始。过去发生的事保持一致；玩家的初始记忆、调查动机、保密清单和个人决定随角色改变。首次访问先选角，已有小仓进度继续接续，也可从“设置 → 选择主角”打开其他故事。

| 主角 | 主要疑问 | 个人支线 |
| --- | --- | --- |
| 小仓信子 | 浅野之死与偏殿袭击 | 留下浅野的证据；追查玉珏与家人 |
| 宫崎正诚 | 自己的一刀造成了什么 | 核对身世；交代刺伤与焚烧 |
| 江一郎 | 断掉的记忆与熟悉的机关 | 恢复旧事；面对宫司的恩情 |
| 石川纪田 | 已经死亡的哥哥为何回来 | 摘下面具后的交代；把选择还给惠美 |
| 加藤太郎 | 众人为何恐惧，记忆为何接不上 | 处理旧案；面对惠美的去留 |
| 加藤惠美 | 家人旧案与身边人的身份 | 留下家人的真实经历；决定自己的去路 |

每人有一条主线、两条个人支线。个人支线需要相应证据，再由玩家作决定；涉及当面归还或交代的决定须先找到对方。选择保存后不重复扣点，后续查看保留原决定。其他五人继续作为 NPC，包括完整的小仓对白、问询许可、夜间证词和最终支线。

石川知道自己的行凶经过；加藤开场不知道死亡真相；江一郎须检查木牌、戒指和面具才能恢复对应记忆。玩家自己的记忆不会直接进入旁人的已知事实。惠美可以自己回想家庭人数，玩家无需向自己出示证据。个人记忆可以作为自己的推理依据，出示给他人后才进入对应听众的记录。

选角页只给公开身份与玩法描述。角色经历与故事页由服务端按当前角色下发，小仓的原故事也从客户端包移入服务端。对白中的固定人物编号与当前玩家身份分开；移动、座位、头像、私谈听众、聊天气泡、语音和计分均跟随当前角色。行动点仍按动作消耗，不使用现实时间。

每个访客拥有六个独立槽位，分别保存线索、笔记、对话、行动点、分数和结局。原 `.json` 小仓存档只读加载时不改写；第一次保存新版结构前留存 `.before-six-roles-v1`。重开只清空当前角色。跨设备同步仍未加入。不同标签页若切换了主角，旧请求会被拒绝，避免写到错误槽位。语音连接同样检查当前槽位。

验收见 `../qa/six-roles-v1/`：六条实际动作路线均可结案并完成两条个人支线、其余五人的支线；七项既有剧情与支线回归通过。桌面六人选角、开场、简介和 SSE 问答通过，手机 390×844 验证惠美路线与草稿重载；桌面、手机均检查所选角色移动。新增丝帛和发簪完成实际点击，个人决定与当面听闻保存通过。HTTP 隔离检查旧档备份、角色切换、单槽重开与双访客隔离；WebSocket 检查换角失效，没有调用 Qwen。

真实 DeepSeek 共抽查八次：先覆盖六个主角，发现两处主语／观察细节不准确，补紧事实与提示后定向复测两次通过。模型对白仍是生成内容，这些抽查不代表穷尽所有自由提问。测试未写入正式存档，14 份原档的哈希、大小与修改时间均保持。

本轮只在 4331 本地实现，没有发布云端。构建共四次：一次工作目录误设后纠正、两次新物件摆位修正后更新产物；本地服务三次有效启动，两次后台启动尝试未驻留。后续类似迭代应在物件点击检查和对白定稿完成后再统一切换服务，减少重复构建与启动。浏览器初测两次使用了错误定位文本，修正测试定位后只补测对应场景；最终页面错误为零。
